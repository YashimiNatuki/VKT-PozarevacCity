# Evidence gates

1. Resolve checkout and baseline. Inventory first-party changes and touched runtime ownership. Preserve independently modified files.
2. Prove rules with targeted tests: invalid inputs, duplicate transitions, interruption and recovery. For cosmetic meshes, test shared source immutability, affected vertex region, finite weights and disposal.
3. Freeze build inputs before Unity validation. Run the applicable suite once after the last implementation edit. Record failures/skips, editor version, platform and test XML digest.
4. Exercise an actual Windows player. Inspect front/side portraits, walking, training and wardrobe for character changes; verify pause ownership and lifecycle cleanup. Screenshot inspection is artistic evidence, not proof of long-session performance.
5. For performance, state hardware, render resolution, scene and duration. Separate startup from steady-state samples. Report median/p95 frame time, sample count and memory growth. FPS from one short run does not establish a stable target. No comparison is valid when capture duration, quality or scene differ silently.
6. For voice, verify license, Serbian language, intelligibility, naturalness and mix by listening. A waveform, filename or passed decoder test cannot approve speech. Show captions when unavailable. Never extract/clone private voices from music without appropriate permission.
7. For terrain, retain CRS and vertical datum provenance. Verify street/footpath continuity, slope, collision and spawn clearance together. A satellite image is not a collision mesh; a DSM may contain trees and roofs.
8. Package only intended files. Bind test XML and artifact hashes to the recorded source scope; explicitly identify incomplete build-input binding. Keep Android installation, touch, audio and sustained FPS as separate hardware checks.
9. Publish only when session-authorized. Verify remote commit, uploaded digest/size and download response. Keep private accounts, keys, models, user saves and personal media out of public source.
